# dsh-awesome-hud

A floating HUD panel for DeepSeek Harness Web and desktop chat pages: session state, context usage with one-click compaction, Git changes, subagents, tasks and MCP switches in one place.

> Click “HUD panel” at the top right of a chat page to open the panel. It shares space with the official right sidebar and [dsh-better-sidebar](https://github.com/omdsh-dev/DSH-better-sidebar): while a sidebar is open the panel steps aside, so nothing is covered and the chat body is not squeezed twice.

## ✨ Feature overview

| Module | What you see and what you can do |
| --- | --- |
| Session | Workspace and session names, run state, one chip for model and reasoning level; menus for rename, pin, branch, archive and copy. |
| Context | Fill ratio and a seven-category bar, session stats and token usage; one-click compaction, or a subagent that writes a handoff document. |
| Usage | DeepSeek balance, OpenCode Go quota and Codex quota; one of them can show in the title while folded. |
| Outputs | Documents, sheets, slides and images this session and its subagents wrote, delivered files and AI-generated images; click to preview, right click to add to chat or copy a path. |
| Git | Branch and change count, staged and unstaged groups, diff, add to chat, reveal and copy from a right click, commit with AI message, git graph. |
| Tasks | The session task list and states, refreshed as the tasks change. |
| Subagent tasks | Subagents of the current session with their states; open one in the right sidebar. |
| Plan list | Plans from plan mode with three states; click a row to read the full plan. |
| Notes | Notes shared by workspace, with images, drag ordering, and import or send to the chat input. |
| To-do | To-do list shared by workspace: check, edit, drag and clear completed items. |
| MCP | Connected MCP servers with global on and off switches. |

The panel also offers **module folding and pinning**, **card and sidebar panel styles**, **left and right panel sides**, and a **built-in usage guide page and changelog page**.

## 🧩 Modules and pages

### Session module

Shows the workspace name, the session name, the session state, and one chip with the model name and reasoning level (the chip color follows the level). Both names are clickable and open a menu at the pointer:

- **Workspace menu**: rename, show in the file manager, copy path;
- **Session menu**: pin or unpin, rename, branch session, copy session ID, copy session name, archive session;
- **Rename**: the name turns into an input in place; Enter saves, Esc cancels and a click elsewhere also saves.

![Session module](docs/module-session.png)

### Context module

The title shows the current fill, the limit and the ratio; the bar color shows the fill ratio. The two lines below hold the session stats (turns, steps, tok/s) and the token usage (total, cache hits). A hover on the bar switches it to seven segments with their share: system prompt, tool definitions, user messages, injected content, skill injections, assistant messages and tool results. The unused part of the window stays grey, and a hover on the lines shows the full details.

- **Compact**: available while the session is idle, greyed while a task runs;
- **Handoff**: the menu to the right of “Compact” starts a subagent that writes a handoff document into `docs/handoff/` of the workspace; progress shows in the Subagent tasks module.

![Context module](docs/module-context.png)

### Usage module

- **DeepSeek balance**: always shown, a dash when there is no data;
- **OpenCode usage**: the usage percents of the three OpenCode Go windows;
- **Codex quota**: the 5-hour and weekly quota for a subscription, the free quota otherwise;
- **Jump**: a click on the balance or a percent opens the matching settings page;
- **Folded info**: while folded, the title can show the balance or one quota, chosen in settings.

The first three lines come from two related plugins: [dsh-account-usage](https://github.com/Ycet/dsh-account-usage) (balance and OpenCode usage) and [dsh-codex-subscription](https://github.com/WSL043/dsh-codex-subscription) (Codex quota). Without them the matching line is hidden and the setting is greyed with a reason.

![Usage module](docs/module-usage.png)

### Outputs module

Lists the documents, sheets, slides and images this session and its subagents **wrote with `write` / `edit`**, the files this session **delivered with the official `present` tool**, and images **generated by gpt_imagegen**: newest first, up to 10 files, with three shown first and the rest opened on click, and the module hidden while there are no outputs. Only these durable records count, so the list survives a DSH restart and never includes files another session or you changed by hand (files produced directly by shell commands no longer appear). A delivered path must stay inside the session workspace, because the sidebar preview resolves against it. A subagent contributes only the `write` / `edit` records in its own log (a fork subagent does not repeat the history it inherited), mapped into the main workspace, so files outside it — a worktree, for example — are not listed. **A branched session** keeps the outputs from before the branch: DSH records no source for a fork, so the plugin identifies the source session from the `owner` fields of the inherited `job` events and checks it against the boundary event, then reuses that session's subagent outputs.

- **Hover path**: a 0.5-second hover on a file row shows the full relative path;
- **Open**: a click opens the file content in the right sidebar;
- **Context menu**: add to chat (an `@` reference in the chat input), show in folder, copy the file name, the relative path or the absolute path.

![Outputs module](docs/module-outputs.png)

### Git module

The title shows the current branch and the number of changed files. Files come in a staged group and an unstaged group with counts, in list or file-tree view: the state letter, the file name, the grey relative directory and the `+added / -removed` counts.

- **Branch button**: switch to an existing branch or create a new one;
- **Init repository**: outside a repository the button reads this; a click makes the repository and writes a `.gitignore`;
- **Hover actions**: staged files can leave the index; unstaged files can be reverted or staged (a folder row applies this to its whole subtree);
- **Context menu**: stage, revert and add to the `.gitignore` in the repository root sit at the top, followed by add to chat, show in folder, and copy name / relative path / absolute path (the same icons the Outputs module uses);
- **Diff**: a left click opens the diff in the right sidebar;
- **Add to chat**: a right click on a file writes it into the chat input as an `@` reference, in both the staged and the unstaged group; a deleted file, a file outside the workspace, or a page without a chat input greys it out;
- **Reveal and copy**: show in folder, and copy the name / relative path / absolute path, exactly like the Outputs module;
- **No clipped menu**: the menu clamps to the viewport from its real item count, flips up near the bottom edge, and scrolls when it is taller than the viewport;
- **Revert**: reverts every unstaged change (untracked files are deleted too) and asks for confirmation first.

![Git module](docs/module-git.png)

#### Graph page

The “git graph” button opens the commit list, loaded page by page (80 commits per page, more when you reach the bottom). The current branch is a blue chip and other branches are grey. A right click on a commit copies the short or full hash or the subject, creates a branch from it, merges it into the current branch, or runs a soft, mixed or hard reset.

![Git graph page](docs/git-graph.png)

#### Commit page

“commit” commits the staged files; “AI generate” writes a commit message from the prompt plus the staged changes. The default prompt holds the date and version rules and can be edited and saved from the top of the dialog. With nothing staged the button still opens the dialog, where commit and AI generate stay disabled.

![Commit page](docs/git-commit.png)

### Tasks module

Shows the task list and states: a running task has a rotating icon, completed tasks stay at the bottom and open on click. The bottom line gives the done, running and pending counts, and the list refreshes as the tasks change. The module stays hidden without tasks.

![Tasks module](docs/module-tasks.png)

### Subagent tasks module

Shows every subagent of the current session, indented by level: a running one is yellow and a finished one is green, and three show first when there are more. A click opens that subagent session in the right sidebar while the main session stays open. The module stays hidden without subagents.

![Subagent tasks module](docs/module-subagents.png)

### Plan list module

Shows the plans from plan mode: yellow for pending approval, green for executed and grey with a strikethrough for discarded, with the counts of the three states below and three rows first when there are more. A click on any row shows the full plan, rendered as Markdown.

![Plan list module](docs/module-plan-list.png)

![Full plan page](docs/plan-content.png)

### Notes module

Notes are shared per workspace (all sessions in one workspace directory use one set), and each note saves its own title and text: no text limit and up to 20 images.

- **List**: the note list shows every note; a click opens the editor and a hover shows the delete button;
- **Order**: drag the handle at the left of a note bar to change the order;
- **New note**: “Add note” starts an empty note in the editor; “Create from chat” starts a note from the input text and images;
- **Delete**: the button turns into cancel and confirm, and a confirm deletes; “Delete all” asks for a confirmation too;
- **Editor**: opens inside the module by default and the back button returns to the list; the title can change (an empty title is numbered), images paste in and reorder by drag, and the bottom handle sets the height shared by all notes;
- **With the chat**: “Import” clears the note first and writes the input content; “Send to chat” clears the input first and writes the note, adding images in note order; “Clear” asks for a confirmation;
- **Dialog editing**: turn it on in settings and a click on a note bar edits it in a dialog while the module stays a list.

![Notes module](docs/module-notes_01.png)

![Note editor](docs/module-notes_02.png)

### To-do module

A to-do list shared per workspace: a check marks an item done and a second click restores it; type in the input and press Enter to add an item; a click on the item text edits it and a delete asks first; drag the handle at the left of a row to change the order; “Clear completed” asks for a confirmation. The title shows the done count and completed items stay below, ready to open.

![To-do module](docs/module-todo.png)

### MCP module

Lists the connected MCP servers and their global on and off state. A click starts or stops a server without a page refresh, and only the target server changes; some setups need a DSH restart.

![MCP module](docs/module-mcp.png)

## ⚙️ HUD settings and panel behaviour

Click the gear at the top right of the Session module to open the settings dialog. The dialog has three tabs: **“HUD settings”**, **“Usage guide”** and **“Changelog”** (the guide is the built-in manual with a heading and one-line entries per topic; the changelog groups the changes by version, and its version list marks the current version as Current).

- **Left pane**: tick modules to show or hide them, drag a handle to set the panel order, and a pin on each card pins that module (one at a time);
- **Right pane**: five cards — HUD panel general settings (panel style: card or sidebar, card by default; panel side: left or right; the two default open states), Context, Usage, Git changes and Notes;
- **Save**: “Save settings” turns active after a change; closing the dialog or Esc discards; “Reset to defaults” opens its menu at the pointer;
- **Disabled rows**: an unavailable setting is greyed and its hint turns red to give the reason.

![HUD settings dialog](docs/hud-settings.png)

Panel behaviour:

- **Open state**: saved per session; the blank session page starts collapsed and the default can be changed in settings;
- **Fold**: a click on a module title folds or unfolds it; Session and Context never fold and the folded state is saved per session;
- **Pin**: a pinned module stays right below Session, up to 40vh, scrolls inside that zone and keeps its sticky title;
- **Sidebar**: the panel hides while the right sidebar is open and returns when the sidebar closes.

## 🚀 Quick Start

**Option 1: install from npm (recommended; the plugin page can update it)**

```bash
# 1. Install (no git required; pnpm must be on PATH for `dsh plugin`)
dsh plugin --profile web add dsh-awesome-hud@0.21.7

# 2. Restart the DSH Web service and refresh the page
```

> [!NOTE]
> A copy installed from npm can be updated from the plugin page: open “Plugins → Installed”, a new version shows “Update available” and the detail page offers “Update to”. Copies installed from a GitHub tag or a Release tarball cannot update in place; uninstall and install again.

**Option 2: install from GitHub (pinned tag; useful without an npm account, no in-place update)**

```bash
# 1. Install (pinned to a release tag; requires git access to GitHub)
dsh plugin --profile web add "github:Ycet/dsh-awesome-hud#v0.21.7"

# 2. Restart the DSH Web service and refresh the page
```

**Option 3: install from local source (development)**

```bash
# 1. Install (replace <absolute-path-to-plugin> with your local source directory)
dsh plugin --profile web add "dsh-awesome-hud@link:<absolute-path-to-plugin>"

# 2. Restart the DSH Web service and refresh the page
```

**Option 4: install from the Release asset (tarball; no git and no npm account needed)**

```bash
# 1. Install (use the Release asset URL directly, or pass a downloaded .tgz path)
dsh plugin --profile web add "https://github.com/Ycet/dsh-awesome-hud/releases/download/v0.21.7/dsh-awesome-hud-0.21.7.tgz"

# 2. Restart the DSH Web service and refresh the page
```

After the install a “HUD panel” button appears at the top right of a chat page (left of the workspace button). **Each session remembers its own open state**; the blank session page is the exception — it starts collapsed every time and offers its own floating button at the top right.

### Desktop install (macOS)

Quit DeepSeek Harness completely, then use the CLI that ships with the desktop app; do not manage the `desktop` profile with an older Web CLI:

```bash
# From npm (recommended)
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add dsh-awesome-hud@0.21.7

# From local source (development)
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add "dsh-awesome-hud@link:<absolute-path-to-plugin>"
```

### Where the data lives

Note text, to-dos, folds, panel settings and the open state live in the `localStorage` of the current browser or desktop app; **note images** are stored as originals in the **IndexedDB** of the same origin. Installing the plugin does not carry this data over from a Web browser, and the model and login credentials stay with DSH.

## 🧪 Development and tests

```bash
# Syntax check
node --check lib/index.js && node --check lib/client.js

# Full suite (checks and aligns the changelog date of the newest version first)
npm test

# Check only / fix the newest version date by hand
npm run changelog:date -- --check
npm run changelog:date
```

`scripts/changelog-date.mjs` guards the date of the newest changelog entry: while that version has uncommitted changes in `lib/client.js`, `lib/index.js` or `package.json` the date is the file write date, and on a clean tree it is the last commit date of those files. A mismatch is corrected to the modification date, released versions keep their own dates, and the check is skipped while `package.json` has a version without a changelog entry. The `pretest` hook aligns it before `npm test`.

Current baseline: **748 tests / 745 passed / 0 failed / 3 skipped**.

```
dsh-awesome-hud/
├── lib/index.js      # Host: routes, git / MCP / subagents / compaction / handoff / settings I/O
├── lib/settings.js   # Settings model and normalisation (order, pin, panel, notes, git)
├── lib/client.js     # Client: panel, modules, settings dialog, guide page, changelog page
├── assets/icons/     # Panel and menu icons (served by the host asset route)
├── cordis.patch.yml  # Plugin declaration and default configuration
└── test/             # node --test regressions
```

## ⬆️ Upgrade Notes (v0.11.x → v0.21.7)

<details>
<summary>Open the per-version notes</summary>

**v0.21.7: The context figures match the official density.** (1) The detail figures no longer freeze: the host cache keyed only on the surface `contentGeneration`, which rises on a replace or a projection and stays put on a plain append, so the seven figures stopped at the first snapshot (skill injections at 142K, assistant and tool results stuck at zero). The cache key now covers the generation, the node count and the last node, and each node is priced once by sequence, so an append invalidates the figures and only new nodes are priced. (2) The estimate now follows the official `dsh-token-meter/src/estimate.ts` line by line: a reasoning block prices as a text block, tool-call arguments count by string length, and a system message counts as plain text density plus role framing. On a real session replay the seven figures add up to the official `messageTokens` exactly (40682 = 40682), and the system prompt matches too (2501 = 2501). (3) Images generated by gpt_imagegen join the outputs module: the MCP's `generate_image` / `edit_image` calls only return a task id, and the image path lands in the `## result` JSON block of the completed `get_image_task` text. The host now scans `tool/result` events, resolves the tool name through the `callId`, and parses `filePath` / `filePaths`; absolute paths normalize against the session workspace, images outside it or already deleted are dropped, and the records share dedupe, ordering and limits with the `write` / `present` evidence. (4) The Git module no longer spins forever when the panel is served from a LAN address (issue #3): the trust fence prefers the official `connection.admit` (DSH removed `requestRejection` in 0.2.3-alpha.1) and the local fallback now accepts the listener bind address like the official `isBindAddressAuthority`, so a self-hosted LAN bind is no longer refused with 403. (5) A git poll that keeps failing (two consecutive beats with no snapshot) ends in an error state with a retry control instead of an eternal spinner; the first failed beat stays on the loading state and heals itself, and a missing session (stale client snapshots after a host restart, just-archived sessions) counts as transient via the 404 `missing-session` code. (6) Drag-reorder can no longer push a pinned module below the top: the drag preview, the saved order and the panel render all keep the pinned module first, and a stale order from an older release is corrected the next time the panel opens. Baseline: 776 tests / 773 pass / 0 fail / 3 skipped.

**v0.21.6: The Git change-file menu matches the outputs menu.** (1) Both the staged and the unstaged group put “Add to chat” in a file's right-click menu. A click writes the file into the chat input as an official `@` reference, through the same logic the outputs module uses: the same reference shape, the same success and failure messages, and the same focus hand-back. (2) A change path comes from `git status --porcelain` and stays relative to the repository root, while an official `@` reference resolves against the session workspace. The snapshot now carries `prefix` (`git rev-parse --show-prefix`), so a session in a subfolder converts the path before the reference goes in. (3) Folder rows get the same “Add to chat”, reveal and three copy items, since an official `@` reference also accepts a folder; revealing a folder goes through the workspace directory route, so a subfolder outside the session workspace still opens. The same menu also offers “Show in folder” and copies the name, the relative path and the absolute path, with the same folder and copy icons the outputs menu uses, now bundled with the plugin and shared by the git graph copy menu and every “show in folder” item. The absolute path needs the repository root, so the snapshot also carries `root` (`git rev-parse --show-toplevel`, realpath on macOS); without it the item greys out with a reason. (4) The menu now lists the git actions (stage, revert, ignore) first, then a divider and the chat and locate actions, then a divider and the copy actions. (5) The menu no longer gets clipped: it clamps to the viewport from its real item and divider count, renders through a portal on `body` instead of inside the HUD panel scroll box, and scrolls when it is taller than the viewport. (6) A file outside the workspace reports that it cannot be referenced, and a deleted file (`D`) or a page without a chat input greys the matching item out with a reason. (7) The context bar hover now splits into seven categories: system prompt, tool definitions, user messages, injected content, skill injections, assistant messages and tool results, each with its estimate and share, while the unused part of the window stays grey. The first two come from the official `contextBreakdown`; the host adds a `context/breakdown` route that scans the session surface and estimates the other five with the official density, then scales them to the official `messageTokens` so the five always add up to the official message total. Without the route the bar falls back to the three segments. The git and context sections of the guide are updated. New cases cover the seven-category estimate, the scaling remainder, the fallback, the menu order and disabled states, and the clamp and portal wiring. Baseline: 761 tests / 758 pass / 0 fail / 3 skipped.

**v0.21.5: the outputs list covers the files this session delivers.** The files the official `present` tool declares (`files[].path`, absolute or workspace-relative) now join the outputs list. They share the same workspace normalization, extension allow-list, de-duplication and ordering as `write` / `edit`, and the evidence stays the durable `tool/call` event, so a restart rebuilds the list. A delivered path outside the workspace is not listed, because the sidebar file preview resolves against the session workspace. Baseline: 748 tests / 745 passed / 0 failed / 3 skipped.

**v0.21.4: the MCP switches match the settings pane, and git diff targeting is fixed.** ① Each row of the MCP module now uses the same switch component as the settings pane instead of the custom green pill: the official `Switch` renders when available, and the local fallback keeps the same geometry and theme tokens, with the brand color for the on track and the theme foreground for the thumb, sized 36×20 instead of 30×18. Clicking still disables that row, refreshes the whole module from the returned snapshot, and drops late answers from older polls. ② The old custom switch styles and their `data-on` state are gone, so the panel keeps one switch style. A new `test/mcp-switch.test.mjs` covers the shared component, the disabled state, the official-first path and the removed styles. ③ **Fixed a left click on a git change row opening the wrong diff**: the old basename fallback matched a same-named file in another directory, so `dsh-awesome-hud/package.json` could open `dsh-archive-manager/package.json`. Matching now uses the exact path or a path-boundary suffix from the repository root to the session cwd. The official turn review is also looked up turn by turn instead of only the latest one, so a file changed in an earlier turn opens its official diff instead of always falling back to dsh-better-sidebar; when that extension is absent, official DSH has no working-tree diff page either, so the clicked file opens in the official file preview instead of a red toast. ④ **Outputs list only what this session and its subagents wrote**: the per-turn change summary is gone, because it is a whole-repository working-tree diff between the turn start and end, so files another session or you changed in the same window were counted as this session's products (session `b086d5e7` showed READMEs from two other plugins). The only evidence now is the durable `write` / `edit` call, which survives a restart; the trade-off is that files produced directly by shell commands no longer appear automatically. Baseline: 745 tests / 742 passed / 0 failed / 3 skipped.

**v0.21.3: subagent outputs and the Current mark in the version list.** ① The Outputs module now covers **this session and its subagents**: documents, sheets, slides and images written by a subagent appear in the list too. The evidence is the durable `write` / `edit` records in the subagent log (rebuilt after a DSH restart, and still without a workspace scan), and every path is mapped into the main workspace, so a subagent running in a worktree or another directory contributes nothing outside it. Originals now come from a module-level `WeakMap` recorded **once, before the first write**, and survive remounts; the cleanup restores a property only when its current value still equals the value the plugin wrote, so host or third-party changes are never overwritten. Two extra triggers were added: a DOM-change reconcile (debounced to one frame) re-resolves the body node and re-applies the reservation so it cannot vanish when the host rebuilds it, and two post-mount re-checks (350 ms / 900 ms) keep a narrow measurement taken mid-animation from becoming final. **v0.15.10: the blank session page no longer shows its floating "HUD panel" entry while a right sidebar is expanded.** Previously that entry moved to the sidebar's left edge and looked collapsed; now any right sidebar (the official one or dsh-better-sidebar) hides the entry entirely, matching the derived-hidden HUD panel, so the button no longer hovers at the sidebar edge where it could be mis-clicked. **v0.15.9: the trust fence now delegates to the official `connection` service.** The HUD host side previously read `ctx.get("webRuntime")?.trustedHosts`, but DSH has never provided a `webRuntime` service, so a trusted-host list could never be resolved for a non-loopback host: with `--host` + `--trusted-host` remote access every HUD `/api/*` route answered 403 (loopback was unaffected, which is why it went unnoticed). The check now calls the official host `connection` service's `requestRejection(request)`, which validates loopback / bind address / `trustedHosts` / `sec-fetch-site` / Origin and requires an authenticated browser Peer in one pass, and falls back to the local check (reading `connection.trustedHosts`, then `webStartup.trustedHosts`) when the service is absent. `engines.dsh: >=0.2.1-rc.2` is now declared so DSH 0.2.2's plugin compatibility gate applies, with two new `test/trust.test.mjs` regressions.


**v0.15.8: fixed MCP switch state rollback and collateral changes to other servers.** The HUD used to rewrite the profile `cordis.patch.yml` itself with a "managed block" and never waited for the host to reload it, which caused two failures: (1) the Loader still held the old state after a click, so the page's 5-second poll reverted the switch; (2) DSH settings persistence appends new rows at the end of the YAML document (before the trailing `# <<<` comment), so those rows landed inside the managed block and the old whole-block rewrite deleted them — a single toggle removed roughly 16 KB of `dsh-connect-workbuddy` configuration, and accumulated pending states made "toggling A also changed B". The legacy managed-block marker comments are cleaned up on the first toggle (comments only; every row inside is kept). The client poll gained a toggle sequence guard so a response started before the click can no longer overwrite the new switch state. Added host regressions in `test/mcp-toggle.test.mjs`, marker-cleanup cases in `test/mcp.test.mjs`, a stale-poll client regression, and updated the desktop integration test. Host-side changes take effect after restarting DeepSeek Harness.

**v0.15.7: the plan list no longer shows "Approved" after "Request changes".** Since DSH 0.2.1-rc.5, the plan review card's "Request changes" button only closes the review and returns to the composer: `exit_plan_mode` no longer throws, it returns a **successful** `{ approved: false }` result while plan mode stays active. The HUD used to treat every successful result as approval, so that plan showed as a green "Approved" in the Plan list module. Successful results are now split by their wording: `Plan approved` means approved, while `dismissed the plan review` means the review was closed and the plan is discarded. **v0.15.5: two silent revert problems fixed, with clearer prompts.** ① Files registered through `git add -N` (intent-to-add, porcelain ` A`) were treated as tracked and went through `git restore`, which emptied the working-tree file while keeping it — they are now removed from the index with `git reset` first, then deleted like untracked files, and the result is verified. ② Untracked directory entries (nested repositories/submodules, porcelain `?? dir/`) were reported as successfully reverted even though `git clean -f` cannot delete them — they are now handled with `git clean -fd` and verified; an all-skipped operation returns an explicit error, while a partially successful one returns the skipped list so the UI can warn. ③ Prompts are clearer: the revert-all confirmation states "N staged file(s) will NOT be discarded", the staged group carries a persistent note, the result toast separates "reverted" from "staged kept", and per-file confirmations explain intent-to-add and staged content. **v0.15.1: two Git module defects fixed, plus a full regression suite.** First, **conflict file lists were lost on the way to the UI** — the host route's error branch forwarded only `error` and `code`, and the client's `call()` copied only `code`, so "Failed to switch branch: local changes in these files block the switch:" ended up empty and merge conflicts always showed the fallback "（no conflict files listed）".

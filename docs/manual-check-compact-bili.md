# 手测清单：git graph 分页按钮与 bili 接管压缩（v0.21.8 同版修复）

> 适用版本：`dsh-awesome-hud` v0.21.8（本清单不涉及版本号变更）。
> 生效方式：**client 改动刷新页面即可**；**host 改动（`lib/index.js`）必须重启 DSH**，否则页面仍是旧进程里的路由。

## 一、git graph「加载更多」

准备：选一个提交数超过 80 条的仓库（首屏一次最多 80 条，`hasMore` 为真）。

1. 打开 git 模块 →「git graph」。
2. 列表首次渲染后直接滚到最底部：**一次**滑动即应出现「加载更多」按钮（旧版需反复上下滑几次）。
3. 不点击、继续在底部上下轻微滑动：按钮**不闪烁、不消失**（迟滞区间 24–120px 内保持原状态）。
4. 点击「加载更多」：按钮区变成加载中，追加下一页后列表变长；此时不再处于底部，按钮消失。
5. 再滚到底部：按钮再次出现，行为一致。
6. 一直加载到没有更多：底部显示「已显示全部」，不再出现按钮。
7. 断网或让 `git graph` 失败后点重试：错误行 + 「重试」按钮显示正常，重试成功后回到第 2–5 步行为。
8. 极短列表（不足一屏）：距底为 0，若还有下一页，按钮应直接可见。

## 二、上下文模块「压缩」

### A. 装有并启用 billion-context（本次重点）

1. 确认 profile 中 billion-context 已启用（会话里能看到它的状态提示即说明已接管）。
2. 会话空闲时点「压缩」文字区。
3. 期望：弹出**警告色**（非红色）提示「billion-context插件已接管官方compact指令，无法进行手动压缩」。
4. 期望：不产生任何压缩、不新增消息、输入框不出现 `/compact`；开发控制台可见一次 `409 bili-managed` 的接口返回。
5. 反复点击：每次都只提示，不报错、不叠加压缩任务。

### B. 未安装或未启用 billion-context（回归）

1. 会话空闲时点「压缩」。
2. 期望：真正执行官方压缩，成功后提示「压缩完成」；上下文占用下降。
3. 会话运行中点「压缩」：按钮置灰不可点。
4. 官方压缩返回 `active compaction`（同一会话并发压缩）：提示「会话正在运行，无法压缩」（409 busy）。
5. 官方压缩返回其它错误：提示「压缩失败：<原因>」——**不能**再出现「压缩完成」。
6. 手动停用 compaction 插件（无 `compaction` 服务、也无 `/compact` 命令、且无 bili 的 `acp` 命令）：提示「命令未注册：/compact」，属预期（不是 bili 场景）。

### C. 交接（相邻功能回归）

1. 点「压缩」右侧下拉箭头 →「交接」：子代理照常生成 `docs/handoff/` 文档，「子代理任务」模块显示进度。

## 三、回归清单

- 中文与英文界面各走一遍 A/B 两节：英文提示应为 “Manual compaction is unavailable: billion-context has taken over the official compact command”。
- 「使用说明」页：上下文一节的压缩说明提到 billion-context 接管；git 一节的分页说明提到底部出现「加载更多」。
- 「关于 → 更新日志」：v0.21.8 出现第二个分组「Git 分页与上下文压缩」，三条要点完整可读。
- 设置面板开合、模块排序、其它模块（用量、产物、MCP、任务）不受影响。

## 四、判定标准

| 项 | 通过条件 |
| --- | --- |
| 分页按钮 | 滚到底部一次即出现；轻微上下滑不闪烁；点击可续页 |
| bili 场景 | 只出现一句警告说明，无任何压缩尝试与失败提示 |
| 官方场景 | 成功/忙碌/失败三态与真实结果一致，不再误报完成 |
| 文案 | 中英一致，更新日志与说明页同步 |
| 版本 | `package.json` 仍为 `0.21.8` |
